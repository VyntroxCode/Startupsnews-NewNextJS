## Tailwind CSS Migration Status

### Styling Rule Going Forward

- **Final target: Tailwind-only codebase, including removal of existing CSS.**
- Do **not** add new custom CSS, CSS Modules, `<style jsx>`, or static inline `style={{}}` props.
- Use Tailwind utilities, arbitrary values, responsive variants, `group`/`peer` states, and `tailwind.config.js` extensions for animations/design tokens.
- Treat all remaining custom/legacy CSS as migration debt to remove, not as a permanent dependency.
- When replacing existing CSS, migrate the behavior into TSX Tailwind classes instead of creating new stylesheet rules.
- Existing CSS may remain only temporarily during incremental migration to avoid breaking pages.

**ALL CONTROLLABLE SURFACES USE TAILWIND IN TSX — LEGACY THEME CSS STILL LOADED (interaction #46 clarified)**
Public pages, public components, and admin UI are authored with **Tailwind utility classes** wherever we control the markup. The project **still loads legacy theme CSS** (`styles/style.css`, `styles/media-queries.css`) plus `globals.css` overrides because the homepage and article layouts depend on **`mvp-*`** and related theme classes until a full redesign replaces that layer. **`@tailwind base` is intentionally not used** — it breaks the theme float/sticky layout (see interaction #9). **Exceptions:** TipTap admin editor (`<style>` injections for editor chrome + pasted content), 410 HTML in `proxy.ts`, Font Awesome CDN `@import` in `globals.css`.

## Reports System

- **Feature scope:** Admin-managed reports library with public member-facing access in the dashboard.
- **Admin routes:** `/admin/reports`, `/admin/reports/create`, `/admin/reports/edit/[id]`
- **Public member route:** `/dashboard/reports`
- **Admin APIs:** `src/app/api/admin/reports/route.ts`, `src/app/api/admin/reports/[id]/route.ts`
- **Public API:** `src/app/api/reports/route.ts`
- **Repository:** `src/modules/reports/repository/reports.repository.ts`

### Reports Data Model

- **Table:** `reports`
- **Columns:** `id`, `title`, `description`, `file_url`, `thumbnail_url`, `file_name`, `file_size`, `mime_type`, `is_active`, `created_at`, `updated_at`
- **Index:** `idx_reports_active_created (is_active, created_at)`
- **Storage:** report files and thumbnails are stored in S3 and referenced by URL.

### Reports Repository Behavior

- `ReportsRepository.ensureTable()` creates the `reports` table if missing.
- The repository also self-heals older production schemas by auto-adding missing columns and the active/created index.
- `file_size` values are normalized to plain numbers before JSON responses to avoid MariaDB `BIGINT` serialization failures.
- Public report listing uses `findActive()` so only active reports are exposed to members.

### Admin Reports Notes

- Admin reports pages use shared admin auth helpers and token fallback handling because some environments strip `Authorization` headers.
- Report upload flow supports direct file upload with S3 presigned URLs.
- Manual fields for file name, file size, and MIME type were removed from admin forms because they are derived automatically from the uploaded file.

### Dashboard Reports Behavior

- `src/app/dashboard/reports/page.tsx` fetches reports dynamically from `/api/reports` using the public auth token from `src/lib/public-auth.ts`.
- The current member page is intentionally simplified compared with earlier iterations.
- Removed from the page UI: summary counters, tag/category pill filters, preview badge overlay on thumbnails, format/pages metadata card, and the remaining reports count text under the search box.
- Current page keeps: hero section, search, report cards, and preview modal.
- The current report cards use a large top thumbnail, oversized editorial title styling, a compact pages/date row, and a bordered right-aligned CTA while still opening the existing preview modal.
- The card proportions were later tightened with a smaller desktop grid, slightly shorter media sizing, and reduced title/meta/button scale for a more compact presentation.
- The cards were then reduced again with a narrower desktop min width, tighter internal spacing, and smaller title/meta/button sizing for an even more compact layout.
- On large screens, the reports grid now uses a fixed four-column layout so four cards can sit in a single row instead of relying on auto-fill behavior.
- Report thumbnails now use contained image rendering inside the media box so the full uploaded image stays visible instead of being cropped.
- Thumbnail boxes now use a soft gradient backdrop derived from each report's color palette so contained images blend into the card more naturally.
- The thumbnail backdrop was later refined into a stronger layered gradient finish with a soft radial highlight so the image area feels more polished and color-led.
- Report card clicks no longer open the old preview modal; they now check `pub_auth_token` and route authenticated users into the dashboard flow while sending unauthenticated users to the public login prompt.

### Current Preview Behavior

- Report cards use `thumbnail_url` as the visual cover when available.
- Opening a report preview uses the uploaded document `file_url` inside a modal when available.
- The preview modal was refined for desktop and mobile sizing so the document uses the available space more cleanly.
- Direct download actions were removed from the member dashboard UI.
- Browser-native PDF toolbar suppression is limited because the preview currently uses the raw document URL in an iframe.

### Operational Notes

- If reports fail with 500s, likely causes previously seen in production were:
  - missing `reports` table columns/index on older schema
  - MariaDB `BIGINT` JSON serialization from `file_size`
  - stripped admin auth headers on admin report pages
- If uploads fail from the browser, S3 bucket CORS must allow the application origin.

### Dashboard Overview Notes

- The old `/dashboard` overview page was removed as the landing surface.
- `/dashboard` now redirects directly to `/dashboard/reports`.
- The earlier dedicated `/api/dashboard/stats` endpoint remains in the codebase, but the dashboard root no longer renders the old overview UI.

### Dashboard Shell Notes

- The shared dashboard sidebar was simplified to a cleaner shell with just the logo, user identity, primary nav items, and logout action.
- The old membership card, secondary nav descriptions, and back-to-site footer action were removed from the sidebar.
- The collapsed desktop rail and mobile drawer were both narrowed so the sidebar behaves better on smaller screens and no longer wastes as much horizontal space.
- In the collapsed desktop state, the brand area now shows only the logo block instead of the full title text.
- The expanded sidebar header was also simplified so the top brand area shows only the logo block, without the StartupNews title text.
- The shared nav was updated so reports is now the primary dashboard destination instead of the removed overview page.

### Dashboard Settings Notes

- `/dashboard/settings` was simplified to remove the extra stat cards, membership benefits, notification preferences, profile tips, quick actions, and danger zone panels.
- The current settings page keeps the profile edit form as the primary surface, with a smaller account snapshot sidebar.
- The profile form area no longer shows the old read-only member/account/status strip, and the copy was updated to avoid membership wording on that page.
